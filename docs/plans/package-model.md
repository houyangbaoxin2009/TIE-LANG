# 规划：tie 库/包模型（多文件包 + tieir 预编译 + 命名空间混合 + port 即接口）

> 状态：**规划**（2026-08-15 设计讨论定稿，未实现）
> 本文档定义 tie 的库模型与包模型。决策汇总：
> **L1c**（多文件包）+ **预编译为 tieir**（分发单元 = tie-IR 中间表示，非 .a 机器码）
> + **L3a+L3b**（全局唯一命名空间 + 包前缀命名空间混合）+ **L4b**（port 即接口）
> + **P1b**（双版本：语言版本 + 包版本）+ **P2c**（最小版本选择，Go 风格）
> + **P3c**（双通道：注册表 + git）+ **P4b**（接口依赖，构建时选实现）
> + **P5a+P5c**（手动发布 + 签名/哈希校验）。
> 关联：接口模型（docs/plans/port-model.md，port 即接口）、UI 框架
> （docs/plans/ui-framework.md，tieuicore 三端复用）、M6 包管理器（已实现 E1-E4）。

## 1. 目标与现状

### 1.1 现状（M6 包管理器 E1-E4 已落地）

- `tie.pkg` 清单 + 三源安装（path/git/registry）+ `tie.lock` 锁文件
- 递归依赖解析（去重/冲突检测）+ `publish`（tar.gz + git tag/push）+ `search/info`
- 库形态：单文件 `.tie` import + `type tie<class>` 编 `.a` 静态库 + namespace 前缀调用
- 多文件并行编译（Harbor M3 协调统筹：tie.config + 三阶段并行）

### 1.2 本次决策解决的问题

1. 库粒度：单文件 → 多文件包（模块化）
2. 分发单元：.a 机器码 → **tieir 中间表示**（平台无关、自带符号/类型信息）
3. 命名隔离：全局唯一 → 包前缀（多版本共存前提）
4. 公共接口：pub 全导出 → **port 即接口**（信息隐藏、实现可替换）
5. 版本策略：单版本 → 双版本（语言 + 包）
6. 解析策略：冲突报错 → 最小版本选择（可复现）
7. 依赖形态：实现依赖 → **接口依赖**（tieuicore 三端复用）
8. 发布：手动 → 手动 + 签名

## 2. 库模型

### 2.1 L1c：多文件包

```
my_pkg/
├── tie.pkg           # 包清单（入口声明 + 元数据）
├── src/
│   ├── main.tie      # 包入口（声明导出面）
│   ├── a.tie         # 包内模块（互相 import 私有）
│   └── b.tie
└── tests/
```

- **包 = 目录 + 清单**：一个库单元，包内多文件互相 import（私有可见）
- **包边界**：包内文件默认私有，只有入口声明的导出对外可见（配合 L4b）
- 小库可单文件（现有形态兼容），大库多文件——同一机制
- 包入口 = tie.pkg 声明的 `main`/`exports` 字段指向的文件

### 2.2 预编译为 tieir（核心决策）

```
源码 .tie ──前端+IR──▶ tieir 文本（分发单元）
                              │
消费方 import：tieir ──语义检查+链接──▶ LLVM IR ──▶ 目标平台
```

- **分发单元 = tie-IR 文本**（compiler/middle/ir.tie 的列式表序列化，
  SSA 值编号，平台无关）
- 发布到注册表/git 的是 **tieir 而非源码、而非 .a 机器码**

**收益**：
1. **平台无关**：同一 tieir 可编译到 win/linux/macos/wasm/嵌入式——
   比 .a 机器码（平台相关）强
2. **自带符号/类型/接口信息**：port 声明、泛型、函数签名全在 IR 里——
   比 .a 更适合接口模型（L4b 的载体）
3. **消费方免前端**：拿到 tieir 直接做语义检查 + 链接 + 生成 LLVM IR，
   编译速度快（复用 M3 缓存池思路）
4. **源码保护**：分发 IR 而非源码（可选，纯逻辑可逆但类型信息完整）

**代价**：
1. tieir 需要**稳定序列化格式**（版本化，跨编译器版本兼容）
2. 消费方需要 tieir 阅读器（语义检查 + 符号解析）——编译器新增一个入口
3. IR 校验（防伪造/损坏）：配合 P5c 签名

### 2.3 L3a+L3b：命名空间混合

```tie
// L3a：全局唯一命名空间（现状，默认）
namespace intern { ... }        // import "./std/intern.tie" 直接前缀调用

// L3b：包前缀命名空间（多版本共存/隔离时启用）
// 包 my_pkg 的模块，import 后以包名限定：
import "pkg:my_pkg" as mypkg
mypkg.ns_a.func()               // 包名::命名空间::函数
```

- **L3a 为默认**：单版本世界，全局唯一，简洁
- **L3b 为升级**：引入包前缀（`pkg:包名`），多版本共存时命名天然隔离
- 切换规则：依赖树无冲突 → L3a 全名直用；检测到同名包/多版本 → 强制 L3b
- 与现有 namespace 兼容：L3b 只是加了 `pkg:` 前缀限定

### 2.4 L4b：port 即接口

```
库的公共面 = port 声明（tieir 中携带）
实现隐藏：impl 块不公开（调用方只见 port，不见具体 struct 实现）
```

- 库发布时**只暴露 port 接口**（L4b），实现细节封装
- 消费方按 port 编译（接口依赖，见 P4b）
- 与接口模型（port-model.md）咬合：port + tieir = 完整的接口分发
- 实现可替换：同一 port 多实现（Win32/X11/wasm 后端切换）

## 3. 包模型

### 3.1 P1b：双版本

```tie
// tie.pkg
name: my_pkg
version: 1.2.3            # 包版本（semver）
tie: ">=2026.1"           # 语言版本约束（tie 本身也在演进）
```

- **包版本**：semver（`^1.2` 约束）
- **语言版本**：包声明所需最低 tie 版本——编译前校验（语言特性演进
  可能破坏旧包，双版本让迁移可管理）

### 3.2 P2c：最小版本选择（Go 风格）

- 解析规则：全依赖图取**最小满足所有约束的版本**（MVS, Minimal Version Selection）
- 与 semver 结合：`^1.2` 约束下取 1.2.x 最低满足者
- **可复现**：tie.lock 锁定精确版本，后续 install 幂等
- 与现状差异：冲突不再直接报错，而是尝试协调到共存版本；
  无法协调（版本约束不相交）才报错

### 3.3 P3c：双通道（现状延续）

- 注册表（index.tie + TIE_REGISTRY 基址）为主：搜索/版本选择/下载
- git 直连兜底：私有包/未发布包（`git+https://...` 或 `git+ssh://`）
- 两者产物统一进 `.tie/deps/`，tie.lock 记录来源

### 3.4 P4b：接口依赖

```tie
// tie.pkg
deps:
  log: "^1.2"              # 实现依赖（现状）
  port:window: "^1.0"      # 接口依赖：依赖 port 而非具体实现

// 构建时选实现
tie build --backend=win32     # 绑定 window port 的 Win32 实现
tie build --backend=wasm      # 绑定 window port 的 wasm 实现
```

- **接口依赖**：声明依赖某个 port（`port:window`），实现由构建参数/配置选定
- tieuicore 三端复用：UI 框架依赖 port（window/draw/event），
  三端分别绑定 Win32/X11/wasm 实现包
- 实现选择：构建参数（--backend）或 tie.config 配置；默认选注册表最新实现

### 3.5 P5a+P5c：发布 = 手动 + 签名

```bash
tie publish          # P5a：手动触发（现状：打包 tar.gz + git tag/push）
```

- **P5a 手动**：发布流程保持手动触发（不做自动 CI 矩阵）
- **P5c 签名**：发布时计算 tieir 包哈希 + 签名（发布者私钥），
  安装时校验（公钥验证，防篡改/防伪造）
- 签名格式：包内附带 `signature` 文件（哈希 + 签名者信息）
- 校验失败 = 安装报错（安全底线）

## 4. 编译流水线（tieir 分发）

```
发布方：
  源码 .tie ──前端──▶ tieir（列式表序列化）
     ├── 签名（P5c）──▶ 注册表/git 发布（tieir + tie.pkg + signature）

消费方：
  tie install ──拉取 tieir + 校验签名（P5c）
  tie build：
    tieir ──语义检查（port/符号解析）──▶ 链接依赖图（P2c 版本解析）
      ──▶ LLVM IR 生成 ──▶ 目标平台（--backend 选实现，P4b）
```

## 5. 编译器实现拆解（tiec 自举）

| 模块 | 改动 |
| --- | --- |
| tieir 序列化器 | IR 结构（ir_funcs_*/ir_blocks_*/ir_insts_*）↔ 稳定文本格式（新增） |
| tieir 阅读器 | 文本 → IR 结构 + 语义校验（新增入口） |
| 包解析 | 包前缀命名空间（L3b）、多文件包入口、私有可见性（L1c） |
| 版本解析 | MVS 最小版本选择（P2c）+ 双版本校验（P1b） |
| 依赖解析 | 接口依赖（P4b）：port 声明解析 + 实现绑定 |
| 签名 | 发布签名 + 安装校验（P5c，哈希 + 公钥验证） |
| CLI | `--backend` 构建参数（实现选择）、publish 签名集成 |

## 6. 决策记录（讨论产物）

| 决策点 | 结论 | 备选（未选） |
| --- | --- | --- |
| 库粒度 | L1c：多文件包（小库单文件兼容） | L1a 单文件、L1b 纯多文件 |
| 分发单元 | **预编译为 tieir**（平台无关中间表示） | .a 机器码、源码展开 |
| 命名空间 | L3a 全局唯一（默认）+ L3b 包前缀（隔离时） | 纯全局、版本化命名空间 |
| 公共接口 | L4b：port 即接口（tieir 携带 port） | pub 全导出 |
| 版本 | P1b：双版本（semver + tie 语言版本） | 单版本、无版本 |
| 解析策略 | P2c：最小版本选择（MVS，可复现） | 统一版本报错、多版本共存 |
| 分发通道 | P3c：注册表 + git 双通道 | 纯注册表、纯 git |
| 依赖形态 | P4b：接口依赖（port）+ 实现依赖并存 | 纯实现依赖 |
| 发布流程 | P5a 手动 + P5c 签名校验 | 自动 CI、无签名 |

## 7. 未决问题

1. **tieir 稳定格式**：序列化格式版本化方案（IR 演进时旧 tieir 兼容策略）
2. **源码 vs tieir 发布选择**：发布方可选发布源码（开源）或 tieir（闭源/保护）？
   若两者并存，消费方路径差异
3. **签名密钥管理**：注册表公钥分发、密钥轮换、信任模型（第一版简化：注册表
   持有公钥，包签名用注册表密钥）
4. **接口依赖的实现发现**：`port:window` 的实现包如何被发现/选择（注册表
   检索"实现此 port 的包"？）
5. **L3b 触发规则**：何时从 L3a 自动升级到 L3b（同名包检测的判定细节）
6. **嵌入式包**：rdu 的 freestanding 约束下 tieir 分发是否一致（IR 平台无关，
   但 rdu 无运行时——链接时排除运行时依赖）
