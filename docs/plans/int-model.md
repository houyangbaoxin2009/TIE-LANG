# 规划：tie 窄整数模型（i8/i16/i32/u8/u16/u32/u64/f32 完整落地）

> 状态：**规划**（2026-08-15 设计讨论定稿，未实现）
> 本文档定义 tie 的窄整数模型——把"类型系统已有、IR 能发、语言层缺失"的
> 窄整数补成完整语言特性，是 repr(C) 互操作与系统编程的前置（unsafe 模型
> 未决问题 #1）。
> 决策汇总：
> **L2+L3**（字面量上下文推断 + 后缀字面量）+ **C2+C3**（拓宽隐式 + 常量缩窄）
> + **O3**（回绕默认 + checked_* 函数族）+ **A1**（窄宽度算术）
> + **B2**（明确移位语义无 UB）。
> 关联：unsafe 模型（docs/plans/unsafe-model.md，repr(C)/extern 互操作）、
> 类型系统（compiler/middle/types.tie，TyKw 已定义）。

## 1. 现状（半支持状态）

| 层 | 状态 | 证据 |
| --- | --- | --- |
| lexer | ✅ 关键字已识别 | i8/i16/i32/u8/u16/u32/u64/f32 全在符号表 |
| 类型系统 | ✅ TyKw 已定义 | types.tie: TK_I8=0...TK_F32=8...TK_STR=13 |
| irgen | 🟡 部分支持 | const_i 按类型发射（i32/i8）、trit 用 i8、char 用 i32、strcmp 返回 i32 |
| semantic | ❌ 无窄整数逻辑 | 类型检查/转换路径无 TK_I8/TK_U32 等痕迹 |
| extern | 🟡 可用 | std/process.tie 先例：`extern fn system(...) -> i32` |

**目标**：把语言层（语义）补完整，并定语义规则——"安全方向自由隐式，
危险方向显式"，与 tie"默认安全、显式解锁"哲学一致。

## 2. 字面量与类型推断（L2 上下文推断 + L3 后缀）

### 2.1 上下文推断（L2，主形态）

```tie
var a: i32 = 42        // 42 按目标类型推断为 i32（常量折叠）
var b = 42             // 无上下文 → i64（默认）
func f(x: u8) { }
f(7)                   // 7 推断为 u8（常量在范围内）
```

- 常量字面量在目标类型范围内 → 自动适配（本质是安全的常量缩窄）
- 无上下文 → 默认 i64（现状保持）
- 超出目标类型范围 → 编译错误（非回绕！）
- 实现：复用现有泛型类型推断（调用点/赋值点上下文传播）

### 2.2 后缀字面量（L3，逃生舱）

```tie
var a = 42i32          // 显式后缀
var b = 7u8
var c = 0x80u16        // 多进制 + 后缀
```

- 无上下文歧义时使用（函数重载/泛型推断不明确的场景）
- 后缀集合：i8/i16/i32/i64/u8/u16/u32/u64/f32/f64

## 3. 隐式转换规则（C2 拓宽 + C3 常量缩窄）

### 3.1 拓宽（C2，隐式允许）

```tie
// 安全方向：窄 → 宽，无信息丢失，隐式
var a: i8 = 7
var b: i64 = a              // ✅ i8 → i64 隐式拓宽
var c: f64 = b              // ✅ 整数 → 浮点隐式（无损方向）
```

- 符号扩展：i8 → i64 自动 sext；u8 → i64 自动 zext
- 拓宽链：i8→i16→i32→i64→f64（无符号同理，u 与 i 之间同宽度不隐式）

### 3.2 常量缩窄（C3，编译期检查）

```tie
var a: i8 = 127             // ✅ 常量 127 在 i8 范围 [-128,127]，允许
var b: i8 = 200             // ❌ 超出范围，编译错误（非回绕！）
var c: i8 = as_i8(big_var)  // 变量缩窄必须显式转换
```

- 常量缩窄安全前提：编译期范围检查（超范围报错，绝不静默截断）
- 这是 L2 上下文推断的底层机制（字面量按目标类型常量缩窄）

### 3.3 显式转换（变量缩窄/重解释）

```tie
var a: i64 = 300
var b: i8 = as_i8(a)        // 显式转换（截断语义，程序员自证）
var c: u8 = as_u8(b)
var d: i32 = as_i32(f64_val) // 浮点 → 整数显式
```

- 转换函数族：`as_i8/as_i16/as_i32/as_i64/as_u8/as_u16/as_u32/as_u64/as_f32/as_f64`
- 语义：数值转换（截断/饱和由函数选择）——第一版只做截断（LLVM trunc/fptosi 直接映射）

### 3.4 禁止（C4 排除）

- **同宽度有符号/无符号不隐式互转**（i32 ↔ u32 必须显式）
- **浮点 → 整数不隐式**（必须显式 as_*）
- **缩窄不隐式**（常量除外，见 C3）

## 4. 溢出行为（O3：回绕默认 + checked_* 函数族）

### 4.1 默认回绕（零开销）

```tie
var a: u8 = 255
var b: u8 = a + 1           // = 0（回绕，LLVM 默认）
var c: i8 = 100 + 100       // = -56（i8 算术回绕）
```

- 编译器零开销（LLVM 原生算术指令）
- 与 A1 窄宽度算术一致（见 §5）

### 4.2 checked_* 函数族（溢出检测）

```tie
var (val, ok) = checked_add(a, 1)   // 返回 (值, 溢出标志)
if ok { ... } else { ... }

var (val, ok) = checked_mul(x, y)
var v2 = checked_sub(a, b)          // 溢出时 panic（断言版）
```

- 函数族：checked_add/sub/mul/div/neg/shl/shr（对 i8..i64/u8..u64）
- 双形态：返回 `(值, 标志)` 二元组 / 溢出时断言（panic）
- 嵌入式（tie:embedded）：断言版 → 编译错误或固定行为（无 panic 环境，
  用标志版）

## 5. 算术语义（A1：窄宽度完成）

```tie
var a: i8 = 100
var b: i8 = a + a           // i8 算术：100+100=200 截断为 -56（回绕）
var c: i16 = a + a          // i16 算术（目标类型决定宽度）
```

- **窄类型算术在窄宽度完成**（LLVM `add i8` 直接支持，irgen 已能按类型发射）
- 类型保持：i8 + i8 = i8；目标类型由操作数类型决定（无 C 整数提升）
- 混合宽度：i8 + i16 → 拓宽到 i16 再算（C2 拓宽规则驱动）
- 排除 A2（提升到 i64 再缩窄）——语义矛盾且慢

## 6. 移位语义（B2：明确无 UB）

```tie
var a: u8 = 0x80
var b = a << 1              // = 0x00（左移移出位丢弃，回绕式）
var c = a >> 1              // u8 逻辑右移 = 0x40（无符号）
// i8 右移 = 算术右移（符号保持）
var d: i8 = -4 >> 1         // = -2（算术右移）

// 移位量 >= 宽度：有定义，非 UB
var e = a << 8              // = 0（左移量 >= 8 → 0）
var f = a >> 9              // u8 逻辑右移 → 0；i8 算术右移 → 0 或 -1（符号）
```

- **移位量 >= 宽度 ≠ UB**：结果有定义（左移 → 0；右移 → 0/符号位）
- 语义由 LLVM 明确（shift 在窄宽度 + 量取模或饱和，由实现定义但明确）
- 与 O1 回绕哲学一致（无未定义行为，tie 全定义语义）

## 7. 与 repr(C)/extern 对接（互操作基石）

```tie
repr(C) struct WndClassW {
    var style: u32          // 窄整数字段（C 布局精确匹配：4 字节对齐 4）
    var cbSize: i32
    var lpfnWndProc: ptr
}

unsafe extern fn win32_fn(x: u32, y: i16) -> i32;   // extern 参数/返回窄类型
```

- repr(C) 结构体字段宽度 = C ABI 精确映射（u32 → 4 字节、i16 → 2 字节，自然对齐）
- extern 参数/返回值窄类型直接映射 LLVM 类型（已有 i32 先例，扩展全部）
- 这是 unsafe 模型 R1/E3 落地的数据基础

## 8. 编译器实现拆解（tiec 自举）

| 模块 | 改动 |
| --- | --- |
| semantic | 窄整数类型检查（类型保持算术）、转换规则（拓宽隐式/常量缩窄/显式 as_*）、字面量上下文推断、范围检查（常量缩窄） |
| irgen | 按类型发射窄宽度算术（已部分支持：const_i 按类型）、sext/zext 拓宽、trunc 缩窄、移位语义 |
| llvmgen | 窄整数 LLVM 类型发射（i8/i16/i32 等，types.tie 已映射） |
| std | checked_* 函数族（窄类型溢出检测）、as_* 转换函数族 |
| extern | 窄类型参数/返回映射（扩展 T0.7 先例） |

## 9. 决策记录（讨论产物）

| 决策点 | 结论 | 备选（未选） |
| --- | --- | --- |
| 字面量 | L2 上下文推断（默认 i64）+ L3 后缀（42i32） | 纯 i64 显式标注 |
| 隐式转换 | C2 拓宽隐式 + C3 常量缩窄（超范围报错）+ 变量缩窄显式 as_* | 零隐式、完全隐式（C 风格） |
| 溢出 | O3 回绕默认（零开销）+ checked_* 函数族 | 检查溢出（trap）、纯回绕 |
| 算术 | A1 窄宽度完成（类型保持） | C 整数提升（i64 再缩窄） |
| 移位 | B2 明确语义无 UB（移过量 >= 宽度有定义） | UB（C 风格） |
| 同宽符号互转 | 不隐式（显式 as_*） | 隐式 |

## 10. 未决问题

1. **f32 的支持深度**：类型系统已有 TK_F32，但浮点窄类型（f32）是否需要完整
   （算术/转换）还是仅 extern 互操作可用？第一版建议：f32 仅 extern/repr(C)
   互操作，算术提升到 f64（避免双精度指令集差异）
2. **as_* 的浮点转换语义**：f64 → 窄整数截断方向（向零截断）确认；溢出饱和
   还是 UB？（第一版：LLVM 直接映射，fptosi 溢出 = poison，unsafe 语义）
3. **常量范围检查的精度**：负数常量到无符号、十六进制字面量范围判定细节
4. **checked_* 的返回形态**：二元组 vs 多返回——取决于语言是否支持
   （第一版二元组）
5. **i128/u128**：是否需要？（系统 API 少见，第一版排除，后置）
