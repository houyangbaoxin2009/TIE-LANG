# 规划：tie 闭包/函数值模型（func 字面量 + move 捕获 + 函数指针 + 协程统一）

> 状态：**规划**（2026-08-15 设计讨论定稿，未实现）
> 本文档定义 tie 的闭包/函数值模型。决策汇总：
> **语法 A3**（func 字面量）+ **捕获 B1**（默认 move）+ **实现 C2**（函数指针+环境指针）
> + **协程统一 C4**（闭包与协程共用机制）。允许递归、允许闭包内 await。
> 关联：内存模型（移动语义+arena）、并发模型（协程/actor/channel）、
> UI 框架（docs/plans/ui-framework.md）。

## 1. 动机与目标

tie 目前**无函数值**：无 lambda、无函数指针、无回调。但三个系统都需要它：

- **并发模型**：`spawn(func)` 捕获环境、actor 的 `on` 消息处理器
- **UI 框架**：事件回调（on_click）、组件工厂、tieuicore 抽象面
- **语言自举**：高阶函数（map/filter/reduce）、回调注册

设计目标：一等公民的函数值，与移动语义/arena/协程**咬合成一个闭环**，
且编译器改动路径清晰（tiec 自举，可迭代）。

## 2. 语法（A3：func 字面量）

### 2.1 函数类型

```tie
// 函数类型：fn(参数类型...) -> 返回类型
var handler: fn(i64) -> i64 = my_func        // 命名函数提升为函数值
var noop: fn() = func() { }                  // 无参无返
```

- 函数类型是**一等类型**：可作变量、参数、返回值、结构体字段
- 命名函数名可直接用作函数值（自动提升）

### 2.2 闭包字面量（func 字面量）

```tie
// 无捕获：等价于普通函数
var double = func(x: i64) -> i64 { return x * 2 }

// 有捕获：捕获外部变量（默认 move，见 §3）
var factor: i64 = 3
var mul = func(x: i64) -> i64 { return x * factor }   // factor move 进闭包
// 此后 factor 在原作用域失效（与移动语义一致）

// 闭包内允许 await（与协程统一，见 §6）
var fetch_all = func(urls: table<string>) -> table<string> {
    var out: table<string> = []
    var i: i64 = 0
    while i < len(urls) {
        out = out + await http_get(urls[i])   // 闭包内可挂起
        i = i + 1
    }
    return out
}
```

### 2.3 递归（允许）

```tie
// 闭包内引用自身 = 递归（C2 函数指针自引用）
var fib = func(n: i64) -> i64 {
    if n <= 1 {
        return n
    }
    return fib(n - 1) + fib(n - 2)   // 闭包内自引用
}
```

- 编译器为递归闭包生成**自引用环境**（环境内持有自身函数指针/入口）
- 无捕获递归闭包 = 普通递归函数（无环境）

## 3. 捕获语义（B1：默认 move）

### 3.1 捕获规则

- 闭包引用外部变量 → 该变量被 **move 进闭包环境**（所有权转移）
- 原作用域中该变量**失效**（使用 = 编译错误，与内存模型 live/moved 检查一致）
- 需要复制时显式 `clone`（与内存模型一致）
- 捕获集合 = 闭包体内引用的所有外部变量（编译器静态分析）

```tie
var a: string = "hello"
var f = func() { println(a) }   // a move 进 f 的环境
// println(a)                   // ← 编译错误：a 已移动
```

### 3.2 环境结构（编译器生成）

```
闭包值 = struct {
    env: ptr,        // 指向捕获环境（捕获变量打包成的结构体）
    entry: fn_ptr,   // 函数入口（见 §4）
}
环境结构体 = struct { 捕获字段1: T1, 捕获字段2: T2, ... }
```

- 环境结构体由编译器按捕获集自动生成（类似匿名 struct）
- 无捕获闭包 = env 为 null，直接指向函数符号（退化为纯函数指针）

## 4. 函数指针与间接调用（C2）

### 4.1 新增函数指针类型

- 语言新增 `fn(A) -> R` 类型，LLVM 映射为**函数指针 + 间接调用**（indirect call）
- 编译器 irgen 需支持：函数地址提升、间接调用指令、环境指针传递
- 这是 tie 首次引入间接调用（现状全部是直接 `call @符号`）

### 4.2 调用约定（统一签名）

```llvm
; 闭包调用统一为：entry(env_ptr, args...) -> ret
; 无捕获闭包：env_ptr = null（或直接调符号，免一次间接层）
```

- 普通函数调用闭包值 → 间接调用 entry，传 env + 实参
- 编译器可为"无捕获闭包"优化：直接调符号，省掉间接层

### 4.3 一等公民能力

- 可存容器：`table<fn(i64) -> i64>`（动态分发成为可能）
- 可作参数/返回值传递（move 语义，所有权随传递）
- 可递归（§2.3）
- 可动态注册回调（UI 事件表、actor 处理器）

## 5. 生命周期（与内存模型咬合）

- 闭包环境分配在 **arena**（或堆）→ 作用域结束整体释放
- 闭包是所有权树节点：move 进 channel/协程 → 所有权随消息转移（并发模型直接可用）
- 无捕获闭包无环境 → 无生命周期问题（纯静态符号）
- 递归闭包：环境含自引用，arena 释放即整体回收（无循环引用问题——自引用不构成 RC 环，
  因所有权是树状：闭包持有自身函数指针是静态引用，不增加引用计数）

## 6. 与协程统一（C4）

### 6.1 统一机制：闭包 = 可挂起的代码块

```
普通函数   = 可调用的代码块
闭包       = 可调用 + 携带环境
async 闭包 = 可调用 + 携带环境 + 可挂起（协程体）
```

- **async 闭包**：函数入口指向协程启动函数（栈式协程的 coroutine entry）
- **调用**：普通闭包 = 间接调用；async 闭包 = 创建/恢复协程执行
- **await 统一**：闭包内 await 挂起当前协程（无论闭包是否 async）
- **spawn 统一**：`spawn(闭包)` = 创建协程 + move 环境进协程帧

### 6.2 闭包与 actor 的咬合

```tie
actor Counter {
    var n: i64 = 0
    // on 处理器 = 闭包（收到消息时调用，环境 = actor 自身状态）
    on Inc() { n += 1 }
}
```

- actor 消息处理器本质是闭包：环境 = actor 状态帧，消息 = 实参
- `send(闭包)`：把闭包（含环境）move 进邮箱 → 接收端调用

### 6.3 闭包与 UI 的咬合

```tie
var btn = ui_button("Click", func() {
    // on_click 回调：捕获 UI 上下文（move）
    state.count += 1
})
```

- 事件回调 = 闭包（环境 = 捕获的组件/状态）
- 组件工厂 = 返回闭包的函数

## 7. 编译器实现拆解（tiec 自举）

| 模块 | 改动 |
| --- | --- |
| lexer/parser | `func` 字面量语法、`fn(..) -> R` 类型语法 |
| semantic | 闭包捕获分析（引用外部变量集）、类型检查（fn 类型）、live/moved 检查（捕获后原变量失效） |
| 类型系统 | 新增 `fn` 类型（含函数指针 + 可选环境标记） |
| irgen | 环境结构体生成、函数地址提升、间接调用指令、env 参数传递 |
| llvmgen | LLVM 函数指针类型、indirect call、coroutine 入口（async 闭包） |
| wasm 后端 | 函数指针 → wasm 间接调用（table）；async 闭包 → 状态机变换 |

## 8. wasm 兼容

- 函数指针：wasm 支持间接调用（table + call_indirect），映射自然
- async 闭包：与 async 函数同策略——wasm 后端编译为状态机（与并发模型 §5.9 一致）
- 环境指针：wasm 内存中管理（线性内存地址即指针）

## 9. 决策记录（讨论产物）

| 决策点 | 结论 | 备选（未选） |
| --- | --- | --- |
| 语法 | A3：func 字面量（复用 func 关键字） | A1 块闭包、A2 捕获列表 |
| 捕获 | B1：默认 move（与内存模型一致） | B2 值拷贝、B3 显式捕获列表 |
| 实现 | C2：函数指针 + 环境指针（一等公民） | C1 单态化展开（零间接）、C3 函数 ID 分发表 |
| 协程统一 | C4：闭包与协程共用机制 | 闭包/协程分离 |
| 递归 | 允许（自引用环境） | 禁止（命名函数替代） |
| 闭包内 await | 允许（与协程统一） | 禁止（async 传染） |

> 注：C1（单态化展开）作为后续优化路径保留——编译器可在调用点类型已知时
> 把闭包调用降级为直接调用（无捕获闭包已天然如此），C2 是语义模型，C1 是优化。

## 10. 未决问题

1. **捕获分析与嵌套闭包**：闭包内再定义闭包，捕获集如何传递（外层捕获需 move 进内层）
2. **环境释放时机**：闭包值离开作用域即释放环境（所有权树析构），与 arena 的关系需细化
3. **fn 类型与泛型的组合**：`func map<T, R>(f: fn(T) -> R, xs: table<T>) -> table<R>` 的
   单态化展开（fn 类型在泛型参数中的实例化）
4. **闭包作为 extern 参数**：extern 回调（C 函数指针）暂不支持（绕开策略：事件轮询，
   见 ui-framework.md §3.5）
5. **调试与错误报告**：闭包内报错的行号/栈信息（间接调用损失调用栈）
