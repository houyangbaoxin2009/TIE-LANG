# tie 泛型系统设计（v1）— 2026-08-14

> 状态：设计定稿，待实现。决策拍板：泛型函数 + 泛型 struct；编译期单态化；
> 声明显式 `<T>` + 调用点类型推断。

## 目标

tie 目前没有用户可定义的泛型（内建 `table<T>` / `map<T>` 是预置类型参数，
不属于语言泛型）。本设计引入：

1. **泛型函数**：`func max<T>(a: T, b: T) -> T`
2. **泛型 struct**：`struct Box<T> { var value: T }`

实例化机制：**编译期单态化**（每个具体类型参数组合展开为独立代码，零运行时
开销；tie 无函数指针、无运行时类型信息，单态化是唯一自然路径）。
类型参数：**声明处显式 `<T>`，调用点从实参推断**（必要时可显式写出）。

## 语法

### 泛型函数定义

```tie
func max<T>(a: T, b: T) -> T {
    if a > b {
        return a
    }
    return b
}

// 多类型参数
func pair<A, B>(a: A, b: B) -> table {
    ...
}
```

- 类型参数列表紧跟函数名：`<T1, T2, ...>`，逗号分隔，允许 1 个或多个。
- 类型参数可在形参类型、返回类型、函数体内出现（作类型使用）。
- 类型参数名允许任意标识符；**作用域内遮蔽内置类型名**（如 `func f<int>(x: int)` 中
  `int` 是类型参数而非内置类型——语义层以 TypeVar 表示，实例化时替换）。

### 泛型 struct 定义

```tie
struct Box<T> {
    var value: T
}
```

- 类型参数列表紧跟 struct 名。
- 字段类型可引用类型参数。

### 实例化（使用点）

```tie
// 显式类型参数
var b = Box<i64>(42)
var m = max<i64>(3, 5)

// 调用点推断（从实参类型）
var m2 = max(3, 5)        // T = i64
var m3 = max(3.5, 1.2)    // T = f64
var b2 = Box("hi")        // T = string（构造参数推断）

// 泛型 struct 方法（数据逻辑分离：绑定命名空间中的泛型函数）
namespace Box {
    pub func get<T>(b: Box<T>) -> T {
        return b.value
    }
}
var v: i64 = b.get()      // T 从接收者类型 Box<i64> 推断
```

- struct 构造 `Box(实参)`：可从构造实参推断；`Box<i64>()`（无参构造）必须显式。
- 方法调用 `b.get()`：T 从接收者实例类型推断（现有方法转发机制不变，目标
  函数是泛型函数时触发推断）。
- 嵌套/组合：`Box<table<i64>>`、`max<table<i64>>(...)` —— 类型实参可为内建
  泛型（mangling 需递归支持）。

## 类型参数语法歧义处理

- lexer 已有 `<` `>` token 与 `>>` 类型参数闭括号分裂（E1，`table<table<T>>`）。
- parser 区分：`<` 紧跟函数名/struct 名/类型引用之后 → 类型参数/类型实参；
  表达式中的 `<` 是比较运算符（操作数上下文）。
- 现有类型引用语法 `table<T>` 的实参解析逻辑可复用为类型实参列表解析。

## 单态化（编译期展开）

1. 泛型定义本身登记为**模板**，不直接生成 IR、不进入普通符号表（或进入但
   标记为泛型，仅实例化后生成可链接符号）。
2. 实例化点（调用 / 构造 / 方法调用 / 显式类型实参）触发展开：
   - AST 复制泛型定义 + 类型替换（TypeVar → 具体类型实参）；
   - 展开产物加入程序（类似 import 展开的函数），递归处理产物内部的新实例化。
3. **去重**：同（函数/struct 名, 类型实参组合）只展开一次（缓存表）。
4. **递归实例化终止**：用户代码类型组合有限；防御性展开深度上限（如 64）
   → 超限报错（中文消息，指明递归链）。
5. 展开后的函数走**现有语义检查**：T 上的操作（比较/算术/方法调用）在替换为
   具体类型后自然被现有类型系统检查——错误在实例化点报告。
6. **符号 mangling**：实例化产物的符号名必须唯一且可读。规则（实现者细化）：
   函数全名 + `$` + 各类型实参的规范化片段（i64→`i64`、f64→`f64`、
   bool→`bool`、string→`string`、用户 struct → 结构名、`table<i64>`→`table_i64`、
   `map<string>`→`map_string`，嵌套递归）。与现有库导出分隔符 `$` 一致。
   struct 构造同理（构造实际是普通函数调用路径）。

## 类型推断（调用点）

- 逐实参匹配：形参类型中 TypeVar 的位置 ← 实参类型（语义层已知类型：
  字面量默认 i64 / 浮点 f64、变量声明类型、struct 实例类型、内建泛型类型）。
- 同一 TypeVar 多处推断必须一致；不一致 → 报错
  （`类型参数 T 推断冲突: i64 vs f64`，中文，定位调用点）。
- 显式类型实参优先：`max<i64>(...)` 指定部分不参与推断；未指定部分继续推断。
- 无法推断（无信息实参，如 `identity<T>()` 无参调用）→ 报错要求显式指定。
- 返回类型含 TypeVar 且由参数推断 → 调用表达式类型 = 替换后的返回类型。

## 约束

- 无显式约束语法（首轮）。
- 合法性由实例化后的现有类型检查保证（C++ 模板隐式约束风格）。
- 错误消息尽量给出实例化上下文：`在 max<i64> 的实例化中: 类型 i64 不支持操作 >`
  （实现者尽力，首轮可简化为实例化点报错）。

## 内建泛型（table<T> / map<T>）

- 内建泛型保持内建，不改为用户泛型。
- 用户泛型实参可为内建泛型实例；用户泛型函数形参可为 `table<T>`（T 为类型
  参数时：`func sum<T>(xs: table<T>) -> T` —— 实例化时整体替换）。

## 实现分层

### Rust 链（crates/tie-frontend + crates/tie-llvm）

1. **ast.rs**：
   - `FnDef` / `StructDef` 增加 `type_params: Vec<String>`（空 = 非泛型，兼容现有）。
   - 类型表示（语义层）增加 `TypeVar(String)` 变体；表达式调用增加
     `type_args: Vec<Type>`（显式类型实参，空 = 纯推断）。
2. **parser.rs**：函数/struct 名后解析 `<T1, T2>`；类型实参列表解析复用
   现有类型参数解析；调用/构造处解析可选 `name<实参>`。
3. **semantic.rs**：
   - 泛型模板登记；实例化展开器（analyze 流程内：收集实例化点 → 展开 →
     去重 → 产物并入符号表后再分析）；
   - 类型推断（调用点实参匹配）；
   - 实例化后错误报告（推断冲突 / 无法推断 / 展开深度超限）。
4. **irgen**（tie-llvm）：展开后无泛型残留；符号 mangling 在函数全名层做。

### tiec（compiler/，自举同步）

- lexer（`type` 已是标识符；`<` `>` 已有）→ parser（泛型列表）→ 语义
  （模板 + 实例化展开 + 推断，tie 表驱动风格）→ irgen（mangling）。
- 双实现行为等价：tests/language/generics.tie 同时用 tie 与 tiec 编译回归。

### 测试

- `tests/language/generics.tie`：泛型函数（max/恒等/多类型参数）、泛型 struct
  （Box 存取、构造推断、显式）、嵌套 `Box<table<i64>>`、方法调用推断、
  错误用例（推断冲突、无法推断、实例化后类型错误）。
- 单态化去重/递归终止的行为测试。
- tiec 行为等价回归 + 自举验证（tiec 编译自身仍绿）。

## 风险与注意

- 自举双实现成本高：Rust 链先行、tiec 跟随，行为等价测试兜底。
- 单态化与现有 import 展开、命名空间/私有可见性（M2.1.7）的交互需在
  展开器中处理（实例化产物归属原命名空间，可见性检查沿用现有规则）。
- `>>` 分裂、`a < b` 比较歧义回归测试需覆盖。
